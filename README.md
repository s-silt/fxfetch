# fxfetch

分发链接取证下载器：粘贴一个分发链接，自动识别形态、按设备身份取回 APK / IPA，并留下可用于调证的访问链路记录。

配套 [fxapk](https://github.com/s-silt/fxapk)（APK/IPA 静态取证分析 CLI）使用：fxfetch 负责「拿到包 + 留下怎么拿到的」，fxapk 负责「包里有什么」。

## 当前状态

**尚无实现。** 本仓库目前只有 [开发任务书](TASKBOOK.md) 与 [执行约定](AGENTS.md)，供执行 agent 按期实施。
任何「已支持 X」的说法，在对应期的验收命令实际跑过之前都不成立。

## 定位

| 做 | 不做 |
| --- | --- |
| 直链 `.apk` / `.ipa` 下载 | App Store / TestFlight 包（显式排除） |
| iOS 企业签、Ad-Hoc：`itms-services` → `manifest.plist` → `.ipa` | 超级签换包（需向对方提交设备 UDID，不做） |
| 按设备身份（Android / iPhone）分别取同一入口 | 爆破验证码、绕过 IP / 地域访问控制 |
| 多跳跳转、Cookie 挑战、简单验证码的会话内自动通过（卡住转人工） | 登录或操作对方后台、提交业务数据 |
| 逐跳留证（实连 IP、TLS 指纹、响应头、时间、哈希） | 包内容分析（交给 fxapk） |

## 红线

- **每一次真正发请求都要操作者授权。** GUI 里点「下载」即为本次授权；CLI 默认零流量，须显式 `--authorized-active`。执行 agent 不得自行加该开关。
- **访问会留下痕迹。** 目标服务器会记录本机出口 IP 与 UA。涉案链接应在专用网络出口访问。
- **下载物是未信任字节，只存不执行。** 不解压到工作目录、不按对方给的文件名落盘。
- **仓库内不出现任何真实域名、IP、令牌、证书或案件信息。** 测试一律用本地靶场与合成夹具。
